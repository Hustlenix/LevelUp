## Sections
**Overview** — The creator's own story (first-person anecdote): a fully-loaded productivity
system (apps, calendars, task managers, colors, reviews) that produced everything except
results — until one "not today" day where he dropped the system and doubled output. The
glitch: more system, less output.

**01 — The addition bias** — The evidence: Adams et al. (2021, *Nature*) — across 8
experiments, people improve systems by ADDING elements, even when subtracting is better;
Klotz's *Subtract* as the practitioner translation. The bias is structural, not personal —
knowing it is half the fix.

**02 — Cognitive load is the tax** — Every tool, toggle, tab, and ritual charges attention
rent: the invisible cost of maintenance (the filter from Ch 1 spends its budget on system
housekeeping). The one-task rule (Ch 25) is the load-reduction surgery.

**03 — The subtraction audit** — The quarterly audit: list every tool, commitment, task,
and meeting you hold; for each, ask "what would happen if this disappeared?" — keep the
indispensable, delete or shrink the rest (the audit IS the Equation Check at system scale).
The subtraction-first principle: before adding anything, remove one thing.

**04 — The glitch in practice** — The "not today" method: one unsystematic day per week —
no task manager, one paper list, one task at a time (Ch 25's loop). What the day exposes:
which tools actually carry weight vs which carry prestige.

**05 — The counter-temptation** — The dangerous moment: when a system works, the bias adds
to it again (success bloat). Institutionalize subtraction: the quarterly audit is
non-negotiable, and "add one, remove one" is the standing rule.

**Key Ideas / Apply Today** — Key ideas: addition bias is structural; load is the tax; audit
quarterly; add-one-remove-one; not-today days. Apply: run a 30-minute mini-audit tonight;
delete one unused tool; run one not-today day this week; write the add-one-remove-one rule
where you'll see it.
