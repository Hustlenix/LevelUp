# LevelUp AI Layer Implementation Plan

> **Execution note:** This approved plan was executed with the user's local-only Ollama override. The implementation may be committed and deployed after verification; unrelated generated artifacts remain protected.

**Goal:** Build a safe local-first Coach, Planner, and Tutor layer with an optional loopback-only Ollama provider and deterministic fallback, compatible with the GitHub Pages static export.

**Architecture:** Add focused `lib/ai` modules for contracts, context, retrieval, prompts, providers, and domain services. Add one additive local AI plan store and a native Study Mode panel. The browser uses deterministic local behavior by default and may call only the user's loopback Ollama endpoint, locked to `llama3.1:latest`; no remote AI service or AI secret is part of this repository.

**Tech Stack:** Next.js 16 App Router static export, React 19, TypeScript strict mode, existing localStorage stores via `useSyncExternalStore`, MiniSearch-generated content data, Node test runner, ESLint.

## Global Constraints

- Preserve `output: "export"` and the GitHub Pages workflow.
- Never add an AI secret, remote AI endpoint, or browser-selectable model to this repository.
- Preserve current uncommitted Study SEO files and generated data changes.
- Reuse existing localStorage stores and existing analytics abstraction.
- Do not add a vector database or speculative hosting infrastructure.
- Reject oversized or malformed inputs and Ollama responses.
- Retrieved/user-provided text is reference data, not instructions.
- Render all AI output as sanitized React text; never execute or inject arbitrary markup.

## Task 1: Add contracts, validators, context, retrieval, and prompts

**Test first:** add tests for bounded prompt input, valid/invalid planner output, compact context, and retrieval ordering.

Expected public interfaces:

```ts
export type AiOperation = "coach" | "planner" | "tutor";
export type AiSource = "local" | "ollama";
export interface AiContext { ... }
export interface PlannerRequest { date: string; availableMinutes: number; objective?: string }
export interface CoachRequest { question: string }
export interface TutorRequest { chapterSlug: string; mode: "explain" | "summarize" | "practice"; level: "beginner" | "normal" | "advanced" }
export function buildAiContext(input: AiContextInput): AiContext;
export function retrieveLevelUpContent(docs: SearchDoc[], query: string, limit?: number): ContentReference[];
export function validatePlannerResult(value: unknown): PlannerResult | null;
export function validateCoachResult(value: unknown): CoachResult | null;
export function validateTutorResult(value: unknown): TutorResult | null;
```

Use explicit limits for question/objective/chapter text, context JSON, result titles, session counts, and durations. Context must contain only summaries and IDs needed by the provider.

## Task 2: Add provider boundary and domain services

Implement:

```ts
export interface AiProvider {
  planner(request: PlannerRequest, context: AiContext, refs: ContentReference[]): Promise<ProviderResult<PlannerResult>>;
  coach(request: CoachRequest, context: AiContext, refs: ContentReference[]): Promise<ProviderResult<CoachResult>>;
  tutor(request: TutorRequest, context: AiContext, refs: ContentReference[]): Promise<ProviderResult<TutorResult>>;
}
```

The local provider must be deterministic for the same input date/context and must refer to real profile, progress, streak, weak subjects, exams, chapters, quizzes, focus sessions, or pillars when those signals exist. The Ollama provider must:

- read only the loopback `NEXT_PUBLIC_LEVELUP_OLLAMA_URL` override in client code;
- reject absent, non-loopback, or invalid endpoint URLs;
- always send model `llama3.1:latest` and never accept a browser-selected model;
- use `AbortController` timeout;
- bound serialized request and response size;
- accept only structured Ollama responses that pass operation-specific validators;
- return a safe error without logging prompts or results.

The service layer calls Ollama only on loopback and falls back to deterministic local behavior on absence, timeout, network failure, non-2xx, invalid JSON, or invalid schema.

## Task 3: Add additive local plan store and safe analytics

Create the plan store with one key such as `levelup-ai-plans-v1` and a bounded record shape. Store generated plans by date and session completion by stable session ID. Keep raw prompts and full provider responses out of storage. Add:

```ts
export function useAiPlanStore(): AiPlanState;
export function saveAiPlan(plan: DailyPlan): void;
export function setAiSessionStatus(planDate: string, sessionId: string, status: "pending" | "started" | "completed"): void;
```

Extend the existing analytics whitelist with events for AI opened, prompt submitted, plan generated/started/completed, recommendation accepted/rejected, and quiz started/completed only where the existing event naming does not already cover it. Send only operation/source/result counts and safe chapter slugs.

## Task 4: Build the native Study Mode UI

Add `AiStudyPanel` to `StudyHome` using existing card, button, color, and spacing conventions. It must include:

- “Generate today’s plan” control;
- available-minutes input with bounds;
- structured session list showing title, duration, type, and reason;
- Start and Complete actions;
- Ask Coach input with a small set of contextual quick prompts;
- tutor controls when a current/recommended chapter is available;
- loading, empty, deterministic fallback, Ollama success, and error states;
- keyboard-accessible buttons and form labels;
- mobile-first responsive layout and reduced-motion-safe transitions.

Do not replace `MissionCard`, existing progress tiles, onboarding, settings, or chapter rendering. The panel is additive and should be usable when the profile is empty.

## Task 5: Document local Ollama setup

Update `.env.example` and a focused documentation section with:

Document that GitHub Pages does not host AI, Ollama must be installed and running on each visitor's own computer, the model is fixed to `llama3.1:latest`, and the current app falls back to deterministic local behavior when Ollama is absent.
